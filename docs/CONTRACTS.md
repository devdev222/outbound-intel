# Operation contracts (HTTP API and MCP)

Generated by `npm run contracts:doc` from `lib/contracts/operations.ts`. Do not edit by hand.

Every operation is available two ways with identical validation and behavior:

- **HTTP**: `POST /api/v1/<name>` with a JSON body. Authenticate with `Authorization: Bearer <machine token>` (scoped; see below) or a signed-in session. Responses are `{ ok: true, result }` or `{ ok: false, error: { code, message } }`. `GET /api/v1` returns this catalog as JSON Schema.
- **MCP**: tool `<name>` on the stdio server (`npm run mcp`). Read-only unless `MCP_SCOPES` grants more. Tools return `structuredContent` matching the output schema.

**Idempotency.** Every mutation takes `idempotencyKey` (provider events use `eventId`). The first call with a key runs; retries with the same key return the stored result and never act twice, across restarts and workers. A retry while the first call is still running gets `in_progress`.

**Pagination.** List operations return `nextCursor`; pass it back as `cursor`. `null` means the last page. Cursors are opaque.

**Errors.**

| code | HTTP | meaning |
|---|---|---|
| `invalid_input` | 400 | input failed validation (details in message) |
| `unauthenticated` | 401 | missing or invalid credentials |
| `forbidden` | 403 | the caller lacks the operation's scope |
| `not_found` | 404 | the referenced record does not exist |
| `conflict` | 409 | the record is not in a state that allows this |
| `in_progress` | 409 | the same idempotency key is still running; retry shortly |
| `internal` | 500 | unexpected failure; safe to retry with the same key |

**Scopes.** Machine identities are configured in `MACHINE_IDENTITIES` (token SHA-256 only). Nothing is implied between scopes.

| scope | grants |
|---|---|
| `read` | Read accounts, briefs, tasks, coverage, model summaries |
| `engagement:write` | Report provider engagement events (email, LinkedIn, identified visitors) |
| `outcomes:write` | Record outcomes (meetings, opportunities, wins, losses) and trigger CRM sync |
| `conversations:write` | Log rep conversations |
| `tasks:write` | Approve, complete or skip tasks |
| `contacts:write` | Research, replace or reject contacts |
| `agents:run` | Run an agent on demand |

### `run_agent`

Run one agent now (icp, hiring, expansion, technology, pain_point, research, contacts, scoring, campaign, video, jerry, learning) or "tick" to run every agent whose cadence has elapsed. Agents may call external providers.

- Scope: `agents:run` · mutation · affects external systems
- Retry: Retry with the same idempotencyKey; agent runs are also guarded by a per-agent lease.
- Errors: `not_found` when unknown agent

Input schema:

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
```
